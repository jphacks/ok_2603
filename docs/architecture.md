# Focus Town 初版の技術設計

## 採用方針

| 用途 | 初版の方針 |
|---|---|
| アプリ形式 | PC・スマートフォン向けブラウザーアプリ |
| フロントエンド | React + TypeScript + Vite |
| サーバー | なし |
| 保存 | ブラウザーのlocalStorage |
| タイマー | ブラウザー標準APIと時刻差分による残り時間計算 |
| 中断検知 | Page Visibility API |
| 街の描画 | オリジナルのシンプルなドット絵 |
| メッセージ | アプリ内に用意した固定文 |
| 外部API | 初版では利用しない |

この構成はログインやサーバーを必要としない試作品に適した方針である。将来アカウント同期、クラウド保存、AIメッセージが必要になった時点で、サーバー構成を別途設計する。

## テーマとの接続と縦方向の完成

学習タイマーと街づくりを掛け合わせ、利用者が完了した作業を街の成長として表現する。初版ではAIやハードウェアを追加すること自体を目的にせず、次の一連の流れを端から端まで動作させる。

`画面操作 → タイマー → セッション状態 → localStorage → 街の表示・メッセージ`

これは初版におけるソフトウェア体験の縦方向の実装範囲を表す。インフラやハードウェアまで含む実装とは区別する。街の表現、住民の言葉、体験設計はチームが考え、ユーザーの実際の作業完了を起点にする。

## デモ方針

- 発表では開始前の街から作業開始、中断・手動再開、作業完了、街の成長、再読み込み後の復元までを連続して見せる。
- 中断演出は街や実績を壊さず、利用者が戻って再開できることが伝わる表現にする。災害や破壊の演出は使わない。演出が罰や失敗と受け取られないか、利用者テストで確認する。
- 25分を待たずに完了経路を実演する必要がある場合は、開発時のみ短縮時間を使う。本番ビルドでは常に作業25分・休憩5分とし、短縮設定を利用者が有効化できないようにする。
- デモ前に、発表で使うブラウザーと画面サイズで全経路を通し、保存データを含む初期状態を準備する。
- デモ手順、確認項目、説明する価値は [デモ・発表計画](demo-plan.md) にまとめる。
- Gitの履歴とREADMEから、変更の意図、起動方法、実装範囲を第三者が確認できるようにする。

## 利用者テストの記録

利用者テストでは、次の内容を匿名の短いメモとして残す。個人情報や詳細な学習履歴は記録しない。

- 対象者が実際に経験した中断と、再開できなかった／できた理由
- 街の成長条件と中断後の状態を、説明なしで理解できたか
- 街が努力の保存や再開に役立つと感じたか、その理由
- 中断演出を罰・損失・再開の合図のどれと受け取ったか
- 既存のタイマーや習慣化手段と比べて、使いたい理由・使わない理由

肯定的な反応だけを選んで発表しない。観察した範囲と限界を明示し、感想を効果の証明として扱わない。

## 画面

1. **街・ホーム**: 街のドット絵、累計作業実績、作業開始ボタンを表示する
2. **作業中**: 25分タイマー、一時停止・再開操作を表示する
3. **休憩中**: 5分タイマーと一時停止・再開操作を表示する
4. **作業完了**: 住民のメッセージと成長した街を表示し、休憩開始を案内する
5. **中断演出**: 一時停止・残り時間・再開方法を伝え、街が利用者の帰りを待つ表現を表示する

画面は単一ページ内の状態切り替えで実装し、初版で複雑なルーティングを導入しない。

## 状態モデル

タイマーの状態は次のいずれかとする。

- `idle`: 開始前
- `working`: 作業中
- `working-paused`: 作業一時停止中
- `break`: 休憩中
- `break-paused`: 休憩一時停止中
- `work-complete`: 作業完了の表示中
- `break-complete`: 休憩完了の表示中

作業時間と休憩時間を定数として分離する。完了時の処理は一度だけ実行し、画面再描画による二重加算を防ぐ。

## タイマー計算

- 毎秒のinterval実行回数を残り時間の根拠にしない。
- 実行開始時刻と終了予定時刻、または残り時間と開始時刻を用い、現在時刻との差から残り時間を算出する。
- `visibilitychange`で`document.visibilityState`が`hidden`になった場合、作業タイマーを即時一時停止する。
- 画面再表示時はタイマーを自動再開しない。
- 再読み込み後に実行中タイマーが勝手に進み続けないよう、復元時は必要に応じて一時停止状態にする。正確な復元方法は実装時にテストで確定する。

## 街の成長

- 完了した25分セッション数を成長実績として保持する。
- 表示する成長段階はセッション数から決定し、中断状態は成長データに書き込まない。
- 初期の試作値として1回、4回、8回の節目を使う。後からしきい値を変更できるよう、成長段階の定義をUIから分離する。

## 保存データ

localStorageには、バージョンを含むアプリ状態を保存する。保存対象は累計完了セッション数など、街を復元するために必要な最小限のデータとする。画像、閲覧サイト、個人情報は保存しない。

保存データのJSONが壊れている場合、アプリ全体をクラッシュさせず、安全な初期状態に戻し、街がリセットされる可能性を利用者に知らせる設計とする。具体的な通知UIは実装時に決める。

## 制約

- Page Visibility APIで分かるのはページが表示中かどうかであり、移動先のアプリやWebサイト名ではない。
- OSやブラウザーによっては、他ウィンドウの表示やバックグラウンド動作を同一条件で検出できない。
- localStorageのデータはブラウザーやサイトデータの消去で失われる。複数端末との同期はしない。
- 初版のセリフは固定であり、AI生成のものではない。
