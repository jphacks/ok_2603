# 旧企画資料: Focus Town デモ・発表計画

> この資料は旧企画（学習タイマーと街づくり）のものです。現在の企画・仕様は [沖縄の選挙公約を公式情報で比較するアプリ](election-app-spec.md) を参照してください。

## 発表で伝えること

中断しただけで努力が無駄になったように感じ、作業へ戻りにくくなることはないか。Focus Townは、学習タイマーと街づくりを掛け合わせ、完了した作業を街に残す。中断は罰にせず、過去の努力を守り、自分のペースで戻れる体験を目指す。

この問題が対象者に実在するか、街が戻る助けになるかは未検証の仮説である。利用者に確かめた結果と限界を合わせて説明し、効果が証明済みとは言わない。

## 実演の流れ

1. **実際の困りごとを説明する**: 対象者が語った中断後の困りごとを紹介し、観察した事実と未検証の仮説を区別する。
2. **解決策と掛け算を示す**: 学習タイマーと街づくりの組み合わせにより、完了した作業を街に残し、中断後も戻れる体験を目指すと説明する。
3. **作業を開始する**: 作業開始を押し、タイマーが動いていることを見せる。
4. **中断から戻る**: デモ中に別タブへ移り、タイマーが停止することを見せる。戻っても自動再開しないこと、残り時間と街の実績が保たれていることを確認する。街が帰りを待つ演出と、手動で再開できることを示す。
5. **作業を完了する**: 手動で再開し、完了後に街が成長して住民のメッセージが表示されることを見せる。
6. **保存を確かめる**: ページを再読み込みし、完了数と街が復元されることを見せる。
7. **実装と検証を説明する**: 画面操作から保存まで動くこと、カメラ・ログイン・外部AI APIを使わないこと、利用者テストで分かったことと未検証点を伝える。

## 短縮タイマーの扱い

25分を待たずに完了経路を実演する場合のみ、開発時の短縮時間を利用する。短縮設定は本番ビルドで無効とし、利用者向け画面から切り替えられないようにする。本番の作業・休憩時間が25分・5分であることを別途確認する。

## 発表前チェック

- [ ] 発表用PC・ブラウザーでアプリを起動し、ネットワーク接続なしでも主要体験が動作する
- [ ] 初期状態または見せたい成長状態を準備し、保存データが想定どおりである
- [ ] 開始、中断、手動再開、完了、成長、メッセージ、再読み込みを一度通して確認する
- [ ] 短縮タイマーを使う場合は開発用であることをチーム内で確認し、本番ビルドに混入していない
- [ ] 中断演出が失敗や不正の罰ではなく、街が帰りを待つ合図として説明できる
- [ ] 画面サイズ、文字、ボタンが発表会場で見やすい
- [ ] 録画・提出が必要な場合は、ライブデモに加えて録画上でも操作と結果が読み取れる

## 利用者テストで確かめる質問

- 最近、勉強や作業を中断したのはどんなときか。その後、作業に戻ったか
- 戻れなかった／戻りにくかった場合、何が障害だったか。今はどう対処しているか
- 何をすると街が成長するか、説明なしで分かったか
- 街の変化や住民の言葉は、作業を終えた実感につながったか
- 中断時の演出をどう受け取ったか。街が帰りを待つ合図に見えたか、罰や損失に見えたか
- この体験を既存のタイマーや習慣化手段より使いたいか。そう思う／思わない理由は何か

最初に過去の具体的な行動を尋ね、誘導的に「使いたいですか」と聞かない。回答は肯定・否定の両方を企画の改善に使い、個人を特定する情報や学習履歴を収集・公開しない。
