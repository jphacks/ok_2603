# 沖縄の選挙公約を公式情報で比較するアプリ（仮称）

## 1. 企画概要

沖縄県内の市町村に住む人が、自分の地域で行われる選挙や候補者を確認し、候補者・政党が公表した公約を分かりやすい言葉で比較できるブラウザーアプリを作る。

チームメンバーが選挙に行くようになり、候補者や政党の公式サイトを読んでも公約を把握しにくいと感じたことが出発点である。情報を集めるだけでなく、地域の選択、関心語による検索、出典の確認までを一続きにする。

この課題が他の利用者にも共通するか、要約が理解に役立つかは仮説であり、対象者への聞き取りと試作テストで検証する。

## 2. 既存サービスを踏まえた位置づけ

選挙ドットコムの「投票マッチング」は、政策に関する質問への回答から、考えに近い政党・候補者との相性を確認するサービスを紹介している。本アプリは質問回答による相性診断を再現せず、利用者が自分で関心語を入力し、該当する公式公約と原文を確認して比較する体験を初版の軸とする。

キーワード検索だけで独自性が確立するとは限らない。沖縄県内の市町村ごとの直近選挙を選べること、地方選挙の候補者情報にたどり着けること、要約ごとに公式出典と確認日を示すことを組み合わせ、既存サービスとの差と利用価値を調査する。

## 3. 対象利用者と課題仮説

- 対象利用者: 沖縄県内の市町村に住み、選挙で候補者の政策を確認したい人。特に、選挙情報を調べ始めた若年層を初期の検証対象とする。
- 課題仮説: 公式サイトや選挙公報が分散していたり、表現が難しかったりして、候補者間の政策を比較しにくい。
- 価値仮説: 地域・選挙から候補者を絞り、関心のある政策語から原文付きの短い要約を並べると、自分で政策を確認しやすくなる。

「若者は政治に関心がない」など、利用者を一括りにする前提は置かない。実際の検索行動と困りごとを聞き、課題仮説を修正する。

## 4. 初版の利用フロー

1. 利用者が沖縄県内の市町村を選ぶ。
2. その地域に関連する直近の選挙を一覧から選ぶ。選挙の種類と実施日を併記する。
3. 候補者一覧から候補者を選ぶ、または選挙内の候補者を比較する。
4. 「子育て支援」「交通」「教育」など関心語を入力する。
5. 該当する公約の要約と、発信主体・原文抜粋または該当ページへのリンク・確認日を確認する。
6. 利用者は出典を開いて原文を確認し、自分で比較・判断する。

## 5. 初版に含める機能

### 必須候補

- 沖縄県内の市町村一覧と地域選択
- 地域に関連する選挙の一覧（選挙の種類、実施日、情報確認日）
- 選挙ごとの候補者一覧
- 候補者・政党の公式発信または公式選挙公報への出典リンク
- 関心語による公約検索
- 公約を短く平易にした要約と出典情報の併記
- 情報未確認・情報なし・対象外を区別した表示
- スマートフォンとPCでの閲覧

初版で対応する市町村・選挙の範囲は、公式情報の入手可能性と制作期間を調査してから確定する。全自治体の網羅を約束せず、未収録地域・選挙も明示する。

### 初版では含めない

- 質問回答によるボートマッチ、相性診断、候補者の推薦
- 候補者・政党の点数化、順位付け、勝者の予測
- 年齢、性別、職業、所得、所属等のプロフィールを使う個別推薦
- 公式発信にない公約の推測や、主張の実現可能性・正しさの独自採点
- 出典不明の報道・SNS・まとめサイトを公約根拠として使用すること
- すべての自治体・すべての過去選挙を網羅しているとの表示

## 6. 情報源・編集ルール

### 情報源の役割

- 選挙の種類、実施日、候補者名、選挙結果等: 沖縄県または各市町村の選挙管理委員会など、選挙を所管する公的機関の情報を確認する。
- 候補者本人の公約: 候補者本人の公式サイト・公式公開資料、または所管機関が公開する選挙公報を確認する。
- 政党の公約: 政党の公式サイト・公式公開資料を確認する。個人候補者の公約と混同しない。
- 公式情報であること、公開主体、参照日、URLを記録する。転載・引用・保存に関するサイトの利用条件も確認する。

公式情報を使うことは、政策内容の中立性・正確性や実現を保証するものではない。候補者・政党の公式発信は当該発信者の主張として扱い、公的機関の情報は選挙事実の確認元として扱う。

### 要約・比較

- 要約は元資料の意味を変えず、評価語や賛否を加えない。
- 要約と同じ画面から根拠となる原文・ページへ移動できるようにする。
- 候補者間で表示項目、文字量、情報の新しさを可能な限り揃える。揃わない点は注記する。
- 見つからない場合は「公約がない」と断定せず、「このアプリで公式情報を確認できず」と表示する。
- 検索結果は関連度のみで恣意的に候補を上位表示しない。候補者の順番は公式掲載順など一貫した規則を明示する。
- 公式資料の表現をそのまま掲載する場合は、引用範囲を明確にし、利用条件を確認する。

### 偏りの抑制

公式発信に情報源を限定しても、発信者ごとの情報量の違い、どの文章を選ぶか、要約の長さ、検索語の扱い、表示順で偏りは生じ得る。公平性を「偏りがない」と断言せず、収録基準、出典、確認日、未収録情報、編集ルールを公開する。候補者の推薦や優劣判定は行わない。

## 7. プライバシーと安全な利用

- 初版ではログイン不要とする。
- 検索語や地域選択は、個人属性と結びつけて保存・分析しない。
- 年齢・職業等のプロフィール入力は実装しない。
- 外部AIサービスへ検索語や利用者情報を送る機能は初版に含めない。
- 利用者に投票先を指示せず、投票判断は利用者自身に委ねる。

## 8. 技術方針（暫定）

- フロントエンド: React / TypeScript / Vite
- PC・スマートフォン対応のブラウザーアプリ
- 初版は小さく動く検索・比較体験を完成させる。サーバー、データベース、自動収集を導入するかは、データ量・更新頻度・公式サイトの利用条件を調べて決める。
- 公約情報には選挙ID、候補者または政党ID、政策テーマ、要約、原文・資料URL、公開主体、確認日、データ更新日を関連付ける。
- 取得方法や更新担当を決められない情報は掲載しない。スクレイピング等は、対象サイトの利用条件と負荷を確認せずに実施しない。

## 9. 検証とテスト

- 対象者が自分の地域の選挙を迷わず選べるか。
- 初見の利用者が関心語から関連する公約を見つけられるか。
- 要約だけでなく出典を開いて原文を確認できるか。
- 要約が原文の意味を変えたり、候補者への評価を含んだりしていないか。
- 情報未確認の表示を「公約が存在しない」と誤解しないか。
- 候補者の表示順やデータの収録差が、特定候補者を不当に有利に見せないか。
- PC・スマートフォンで検索・比較・出典確認が利用できるか。
- 公式情報の公開主体、参照URL、確認日、更新日が記録されているか。

少人数のテスト結果を、全有権者に有効である証拠として扱わない。良い反応だけでなく、検索できない、比較しづらい、要約を信頼できない等の意見も記録する。

## 10. デモ案

1. 市町村を選び、その地域の直近選挙と実施日を表示する。
2. 候補者一覧から政策を見たい候補者を選ぶ。
3. 「子育て支援」などの関心語で検索する。
4. 複数候補の公約要約と出典情報を同じ形式で確認する。
5. 公式の原文を開き、要約の根拠を利用者が確かめられることを示す。
6. 未収録情報や確認日も隠さず提示し、推薦や点数付けをしない設計を説明する。
