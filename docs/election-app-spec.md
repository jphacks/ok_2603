# 沖縄の選挙を知り、自分で考えるアプリ（仮称）

## 1. 目的

沖縄県内の若者が政治や選挙に関心を持つきっかけをつくり、実際に投票先を考えるときには候補者・政党の公約や公式記録を自分で確認し、比較できるよう支援する。

候補者を採点して「あなたに合う人」を推薦するのではなく、政治を知る入口から公式情報に基づく比較までを一つの体験として提供する。投票先を決めるのは利用者自身である。

チームメンバーが選挙に行くようになり、公式サイトを読んでも公約を把握しづらいと感じたことが出発点である。この課題が他の若者にも共通するか、用語解説や比較画面が判断の助けになるかは、利用者テストで確かめる仮説とする。

## 2. 利用者の流れ

1. クイズや用語解説から、政治・選挙について気軽に知る。
2. 沖縄県内の市町村を選び、対象地域の選挙と候補者を確認する。
3. 「子育て支援」「教育」「交通」など、自分の関心語で公式公約を探す。
4. 候補者ごとの公約、具体性に関する記載、公式出典を同じ形式で比較する。
5. 現職・再出馬候補の場合、公式な過去の公約や議会活動記録が確認できる範囲で参照する。
6. 原文や公式記録を開き、自分で考えて判断する。

## 3. 初版の優先度

### MVP（まず動くものとして完成させる）

- 沖縄県内の市町村・選挙を選ぶ。初版で実際に収録する地域・選挙は公式情報の入手可能性を確認して決め、網羅できない範囲を明記する。
- 選挙ごとの候補者一覧を表示する。
- 「子育て」「教育」「交通」などの関心語で公約を検索し、候補者ごとに比較する。
- 各公約について、平易な要約、情報の発信主体、公式出典、確認日を表示する。
- 公約の具体性は点数にせず、「対象者」「実施時期」「方法」「財源」「成果の確認方法」等の記載箇所を項目別に示す。記載を確認できない項目は「記載を確認できず」とし、能力・実現可能性の評価とは区別する。
- 難しい政治・選挙用語の短い解説を、信頼できる公的な情報源とともに表示する。
- 初心者向けの中立的な政治・選挙クイズを用意する。政策への賛否や候補者の優劣を正解として問わない。
- PC・スマートフォンで主要な流れを利用できる。

### 追加候補（公式データの有無と制作時間を確認してから実施）

- 現職・再出馬候補の過去の公約と実施状況、議会での発言・採決等の記録。公式記録が見つかる場合に限り、記録の種類、期間、出典、確認できない範囲を併記する。「公約達成率」等の単純な点数にしない。
- 選挙管理委員会等が年代別の投票率を公表している場合、その統計を対象選挙・公表主体・出典とともに紹介する。利用者の年齢や投票先は収集しない。
- 追加する場合も、未収録・非公表を「実績なし」「投票しなかった」と誤解させない。

初版では、有権者の年代別投票先を集計・公開しない。投票先は機微な政治的情報であり、独自調査には標本の偏りやプライバシー上の課題がある。年代別の投票率と投票先の割合は明確に区別する。

## 4. 中立性・編集ルール

- 選挙の事実（選挙日、選挙種別、候補者名等）は、沖縄県・市町村の選挙管理委員会等、選挙を所管する公的機関の情報で確認する。
- 公約は候補者本人・政党の公式発信、または選挙管理委員会等の公式選挙公報を出典とする。候補者個人の主張と政党の主張を混同しない。
- 用語解説、クイズの解答・説明には、公的機関等の出典と確認日を付ける。クイズは制度・手続などの事実を扱い、特定の政策への賛否を誘導しない。
- 要約は原文の意味を保ち、評価語や賛否を加えない。根拠となる公式資料へ利用者が進めるようにする。
- 候補者を推薦・採点・相性判定しない。比較項目の有無は、資料に記載を確認できたかを示すもので、実現可能性・政策の良し悪しの判断ではない。
- 候補者間で同じ項目・形式を使い、表示順は公式掲載順など一貫した規則にする。収録状況に差があれば明記する。
- 見つからない場合は「公約がない」と断定せず、「公式情報を確認できず」と表示する。
- 公式情報を使っても、情報量の違い、選ぶ箇所、要約、表示順で偏り得る。「偏りがない」と断言せず、出典・確認日・編集方針・未収録範囲を公開する。
- 引用・転載・保存の利用条件を確認する。条件や出典が確認できない資料は掲載しない。

## 5. 共通データ形式（実装前に全員で合意）

機能を並行して作れるよう、まず次の概念とフィールドを共有する。実際の型定義はコードで一か所に置き、担当者ごとに似た型を重複作成しない。

| データ | 初版で持つ主な項目 |
|---|---|
| 選挙 | ID、市町村、選挙種別、実施日、公式情報URL、確認日、収録状態 |
| 候補者・政党 | ID、表示名、選挙ID、公式に確認できた所属、公式プロフィールURL、公式掲載順 |
| 公約 | ID、候補者または政党ID、政策分野、検索語、平易な要約、具体性チェック項目、出典ID |
| 出典 | ID、公開主体、資料名、URL、資料種別、参照日、利用条件の確認メモ |
| 用語・クイズ | 用語または問題文、説明・選択肢、正答根拠、公的出典ID、確認日 |
| 過去の活動・統計（追加候補） | 対象者・期間・記録種別・値または事実、公式出典ID、確認日、対象範囲・限界 |

共通フィールドは、選挙ID・候補者IDなどの関連ID、出典ID、確認日、情報状態を基本にする。未確認、該当データなし、対象外を区別し、空欄を推測で埋めない。

## 6. 6人の作業分担（Issue #2〜#7）

担当者名はチームで決め、各Issueに割り当てる。実装の並行着手前に、Issue #2で共通データ形式・初版範囲・情報源ルールを短く合意する。その後は共通仕様に沿って分担作業を並行し、動く仮データを使って統合する。

| 担当 | Issue | 成果物・範囲 |
|---|---|---|
| 1 | #2 公式情報源・初版範囲・共通データ形式 | 初版の選挙範囲、公式情報の調査方法、共通データ契約を決める。実装担当間の質問窓口も担う。 |
| 2 | #3 選挙・候補者の公式データ | 合意した範囲の市町村、選挙、候補者情報を出典付きで整理し、共通形式にする。 |
| 3 | #4 地域・選挙選択と共通画面 | 市町村・選挙・候補者を選ぶ画面と、各機能に移動するナビゲーションを作る。 |
| 4 | #5 公約検索・比較・具体性チェック | 公約表示、関心語検索、候補者間比較、出典表示、記載項目チェックを実装する。 |
| 5 | #6 用語解説・政治/選挙クイズ | 公式出典付き用語集と、中立的な制度・手続クイズを作成・実装する。 |
| 6 | #7 過去記録・年代別投票率の実現可能性調査と統合検証 | 公式データの有無を調べ、実施可能なら追加機能として小さく実装する。無理に実装せず、利用フロー・出典・表示の総合確認とデモ準備を行う。 |

### 進め方

1. チーム全員でIssue #2の共通データ形式とMVP対象範囲を確認する。
2. 各担当は共通データ形式を使い、他担当のファイルを直接変更せず、別ブランチで並行作業する。データ契約の変更が必要なら先に相談する。
3. データが揃う前も、同じ型の少量の仮データで画面・検索・クイズを進める。仮データを実データとして誤表示しない。
4. PRを小さく作成し、少なくとも別のメンバー1人が確認してからmainに取り込む。
5. 統合担当は全機能をつなぎ、テスト担当とともに公式出典・未収録状態・スマートフォン表示を確認する。
6. 追加候補はMVPの主要フローが動いた後に判断する。時間が足りない場合は追加候補を外し、MVPの正確さと完成度を優先する。

## 7. 技術・プライバシー方針

- フロントエンド: React / TypeScript / Vite。PC・スマートフォン向けブラウザーアプリとする。
- 初版はログイン不要。年齢、職業、政治的意見、投票先などのプロフィールを収集しない。
- 検索語・地域選択を個人と結び付けて保存・分析しない。外部AIサービスへ利用者情報や政治的関心を送信しない。
- データ量、更新頻度、利用条件を調べてから保存・配信方式を選ぶ。利用条件や負荷を確認せずスクレイピングしない。
- データの公開・更新担当、確認日、更新日、誤りの連絡方法を分かる形にする。

## 8. MVP完了条件と検証

- 市町村選択から選挙、候補者、公約検索、比較、出典確認まで一続きで動く。
- 用語解説とクイズに公的な根拠があり、政治的賛否や候補者の優劣を正解としていない。
- 掲載するすべての選挙事実・公約に確認可能な公式出典と確認日がある。
- 要約・具体性チェックは原文と照合し、採点や推薦に見えない。
- 情報未確認と情報なしを区別し、未収録データが公約不在と誤解されない。
- PC・スマートフォンで主要操作が使え、キーボード操作も確認されている。
- 可能であれば対象者3〜5人に、知識コンテンツと投票前の比較フローを試してもらい、肯定・否定両方の意見と未検証点を匿名で記録する。
- 過去の活動や年代別投票率を追加する場合は、公式な出典・対象期間・定義・限界を表示し、MVPを遅らせない。

少人数の利用者テストやチームの自己評価を、全若者への効果の証明として扱わない。

## 9. デモ案

1. クイズまたは用語解説で政治・選挙を知る入口を見せる。
2. 沖縄県内の市町村と選挙を選ぶ。
3. 「子育て支援」等で公約を検索し、同じチェック項目・形式で比較する。
4. 要約の根拠となる公式資料、発信者、確認日を開いて示す。
5. 「推薦や採点はせず、判断に使う情報を整理する」方針を伝える。
6. 追加データを実装した場合のみ、対象範囲や限界とともに過去記録・公式投票率を紹介する。

## 10. 先に確定すること

- 初版で扱う市町村・選挙種別と「直近」の定義
- 共通データ形式のTypeScript型、ID規則、公式出典の必須項目
- MVPと追加候補の境界、6人の担当者名
- 公約の具体性チェック項目と「記載を確認できず」の扱い
- 用語・クイズに使う公的情報源と更新担当
- 各公式情報の利用条件とデータ更新方法
- 過去の公約実施状況・議会活動記録・年代別投票率の公式データ入手可能性
- 既存の投票マッチング等と異なる利用価値があるかを、対象者に確かめる方法
