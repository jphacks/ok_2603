# データファイルの編集と確認

登録先: `src/election/data.ts`。型定義: `src/election/model.ts`。

## 登録手順

1. 担当者が公式資料の本文を確認する。AIの推測や検索結果の要約を確認済みの根拠として登録しない。
2. 作業ブランチで選挙、候補者、必要な用語を追加する。選挙IDと候補者IDは一意にする。
3. 公式HTTPSリンク・発行元・実際に確認した日（YYYY-MM-DD）を各項目に付ける。公式サイトかどうか、引用が適切かは人が確認する。URL形式チェックは公式性を保証しない。
4. `npm run validate:data`、`npm test`、`npm run build` を実行する。
5. PRで資料と記載内容をレビューする。今後の本格的な公開承認フローを定めるものではない。

選挙・候補者・現職県議の公開データは現在空配列。政治・選挙の用語解説は81件収録。テスト専用の氏名・本文はtestsとUIテストに隔離され、公開ファイルには含まれない。

## 選挙一覧APIとSupabase

`GET /api/elections` はSupabaseの `public.elections` を参照する。必要な列は `id`, `name`, `municipality`, `voting_on`, `official_url`。市町村を指定した場合は、その市町村の選挙に加えて沖縄県全体の選挙も返す。選挙種別は登録名から判定する。公式URLの確認日がDBにない場合、画面には確認日未記録と表示する。

Supabaseの選挙一覧は公開情報として匿名ロールから読み取る。新規環境では `supabase/migrations/202610180002_public_election_catalog.sql` を適用し、RLSで選挙カタログを読み取り可能にする。候補者・公約の収集データは引き続きローカルSQLiteを使用するため、Supabaseに選挙行を登録しただけでは候補者・公約は収録されない。

那覇市長選（第24回、投票日2026-10-25）は、公式特設ページの情報を `supabase/migrations/202610180003_naha_mayor_election.sql` で登録する。候補者一覧PDF（2026-10-18午前9時30分現在）で確認した4人を `src/election/data.ts` に掲載し、候補者の絞り込み・比較に利用する。選挙公報は公式ページで準備中のため、公約・AI要約は資料公開後に確認・登録するまで「公約公開前」と表示する。スマートフォンでは候補者ごとのカードで要約を読み比べ、比較対象を絞り込める。詳細な具体性チェックは候補者詳細とデスクトップ比較表で確認する。

## 現職の沖縄県議会議員

`councilMembers` は選挙ごとの `candidates` と分けて管理する。今回は専用画面だけを実装し、収録データは空配列とする。選挙の候補者や過去の当選者から現職議員を推測しない。

登録項目は `id`, `name`（氏名）, `faction`（会派）, `district`（選挙区）, `sources`。会派・選挙区が未収録なら `null` を指定する。各議員には公式URL・発行元・確認日を含む出典が必要。現職であることと所属情報を公式資料で確認してから登録する。専用画面は氏名・選挙区の部分一致検索に対応し、写真・公約・個別詳細ページは含めない。

## 市町村の読み仮名

`model.ts` の `municipalityReadings` に41市町村の読みを管理する。名称・読みの根拠は[沖縄県「沖縄県内の市町村」](https://www.pref.okinawa.lg.jp/machizukuri/jutakutochi/1012354/1012440.html)（2026-10-18確認）。既存の市町村名配列・地域への画面遷移は正式名称を使用する。

検索ではひらがな・全角／半角カタカナを正規化し、1文字から名称・読みの部分一致で候補を更新する。完全一致、前方一致、その他の部分一致の順に並べる。

市町村に対応する県議会議員選挙区は `model.ts` の `prefecturalDistricts` で管理する。13選挙区・41市町村の対応の出典は[沖縄県議会「県議会の組織」](https://www.pref.okinawa.lg.jp/kensei/gikai/1016969/1016972.html)（2026-10-18確認）。県議選の `Election.district` には正式な選挙区名を指定する。未指定の既存データは、選挙名中の正式選挙区名または明示された市町村名で照合する。出典は市町村選択後の地域画面に表示し、ホームの装飾地図とは区別する。

## 状態

- `recorded`: `value` と1件以上の `sources` が必須。5項目チェックのvalueは資料中の根拠文章を登録する。
- `unrecorded`: 未登録。valueや出典を捏造しない。
- `not-confirmed`: 確認した資料で確認できなかった。`note` に確認範囲・理由、`sources` に確認した資料を登録する。
- `no-record`: 公式資料の指定範囲に該当する記録がないことを確認した。`note` と `sources` が必須。「検索で見つからない」をこの状態にしない。

出典型: `{ url, publisher, checkedAt }`。画像も出典を付け、許諾を確認する。

選挙: `id`, `name`, `prefectureIds`（対象の都道府県名の配列）, 任意の `municipality`, `level`（national/local）, `period`（current/past）, `date`（投票日）, `sources`, `turnout`。

この試作品の対象は沖縄県のみ。`prefectureIds`には「沖縄県」だけを指定し、他都道府県の情報は登録しない。国政選挙も沖縄県の有権者に関係する情報に限る。全国の選挙区や自治体データを自動収集・推測する機能はない。

投票率は `Entry<{ age: string; rate: number }[]>`。rateは0～100、未収録を0%で表現しない。年代や標本抽出の範囲は公式資料に合わせ、必要な説明を出典とともに登録する。

候補者: `id`, `electionId`, `name`, `party`, `photo`, `pledges`, `profile`, `speeches`, `votes`, `history`, `sources`。

候補者名を使い回して別選挙のデータを混在させない。同じ人物でも選挙ごとのレコードを明示する。比較表は選挙名も表示する。

公約: `id`, `text`, `checks`。checksのキーは型定義の5項目と一致させる。すべて未収録の場合は `emptyChecks()` を利用できる。

用語: `term`, `definition`, `sources`。短く中立な説明と公的出典を登録し、「用語」から検索できます。`glossaryReadings` にすべての用語のひらがな読みを登録し、一覧ではふりがなとして表示します。公約文中では最長の一致語から認識し、用語名をHTMLとして解釈しません。

管理画面は未実装。認証方式、保存先、公開承認、ファイルとの連携方式を決めてから、この型に沿った入力・検証機能を実装する。
